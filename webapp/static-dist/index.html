The problem

A security bump is two walls, not one

Exploiting a known vulnerability is now the most common way a breach starts, ahead of stolen credentials, and the median time to actually patch one has climbed to 43 days and is still rising (Verizon 2026 DBIR). Dependabot, Snyk, Renovate and Mend are superb at telling you what to upgrade. Then they open a version-bump PR and stop.

Two things keep that PR from ever turning green, and both are exactly what an autonomous agent should own.

Wall 1 · the fact

Which version is even safe?

A CVE disclosed this month post-dates every model's training cutoff. Ask a plain model for the fixed version and it cannot know it. The honest ones say so; the rest guess.

Wall 2 · the break

The fix breaks the build

The safe version is often a major release that removed an API you used. So the upgrade that closes the CVE turns your tests red, and the PR rots unmerged.

Where it fits

The last mile your scanner leaves open

LiveFix is not another scanner. It is the one step every scanner leaves to you: scan, alert, bump PR, and then today a human, or a PR that rots. We sit on top of the scanner you already run and turn its red bump PR into a green, merge-ready change. The wedge is a partnership, not a fight: your scanner says what is broken, LiveFix lands the fix.

The product follows directly: a GitHub App billed per repository, triggered by the alert you already receive, and measured in the number security leaders now report to their board, mean time to remediate. Every advisory landed green is engineer-hours saved and days off an MTTR that the EU Cyber Resilience Act and the SEC disclosure rules are turning into a hard obligation.

The unit economics are stark, and we measured them: a remediation costs roughly 0.002 to 0.01 USD in model compute and finishes in seconds to about a minute, against the one to three engineer-hours a breaking security upgrade takes a senior to resolve by hand. LiveFix reports the exact tokens and cost on every run.

How you use it

One command, or zero

LiveFix does not scan for vulnerabilities, your scanner already does that. You hand it a flagged advisory and it evaluates and produces the safe upgrade, proven by your own tests. Two ways to run it.

Run it yourself

As a CLI

Point it at a project and an advisory.

python -m livefix.remediate \
--project . --package pillow \
--advisory CVE-2026-112398 \
--test "python -m pytest -q"
Zero touch

As a GitHub Action

A scanner alert opens a verified PR on its own.

- uses: novacorp-labs/livefix@v1
with:
package: pillow
advisory: CVE-2026-112398

Bring your own keys: the CLI reads a local .env, the Action reads your repo secrets, never the code. Use dedicated CI keys with a spend cap. Setup guide.

The stack, and what each part does

Four services, one job each

Tavily

The fact

Live web search supplies the one thing the model cannot hold: the safe version of a CVE disclosed after its training. The load-bearing step.

NVIDIA Nemotron

The repair

The open model nemotron-3-super-120b-a12b writes the minimal patch for the code the upgrade broke, and abstains instead of guessing.

Nebius Token Factory

The compute

Serves the model behind an OpenAI-compatible endpoint, so the official SDK runs it with one base URL and key. No GPU on your side.

LangSmith

The trail

Optional tracing records every resolve, search and model call, so each remediation is auditable. The evidence behind the verified mark.

Why it matters: remove any one and the loop breaks. No Tavily, no fact; no Nemotron, no fix; no Nebius, no model; no trace, no proof. Each service does exactly one load-bearing job.
